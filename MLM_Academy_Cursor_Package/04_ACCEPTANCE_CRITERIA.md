# Критерии приёмки оболочки MLM Academy

Cursor должен пройти этот список перед завершением.

## 1. Целостность данных

- [ ] Загружено ровно 112 треков.
- [ ] Track ID уникальны.
- [ ] Каждый ID соответствует `^A[1-6]-[0-9]{3}$`.
- [ ] Распределение: A1 — 16, A2 — 16, A3 — 17, A4 — 17, A5 — 14, A6 — 32.
- [ ] Приоритеты во внутреннем валидаторе: P0 — 36, P1 — 66, P2 — 10.
- [ ] Все `nextTrackIds` существуют в каталоге.
- [ ] В pilot graph 16 уникальных узлов.
- [ ] `sections.json`, каталог и graph проходят схему/валидацию при build.
- [ ] Компоненты не содержат вручную скопированных массивов карточек.

## 2. Защита внутренних данных

- [ ] Публичный тип не содержит `priority`, `source`, `adaptationLevel`, `transformationType`, `internalNote`, `pageStatusRaw`.
- [ ] Внутренние поля не попадают в HTML, RSC payload, публичный API и client bundle.
- [ ] Источник Рыбкина и номера страниц не отображаются пользователю.
- [ ] Production не показывает planned/draft/review/archived.
- [ ] Preview включается только серверным флагом.

## 3. Маршруты

- [ ] Работают `/`, `/start`, `/library`, шесть `/library/a1`–`/library/a6`.
- [ ] В preview открывается оболочка каждого из 112 `/track/aN-NNN`.
- [ ] Uppercase URL нормализуется или редиректит на lowercase.
- [ ] Неизвестный Track ID даёт нормальный not-found.
- [ ] Работают `/my`, `/my/route`, `/my/results`, `/profile`, `/access`.
- [ ] `/admin/catalog` недоступен обычному production-пользователю.
- [ ] Все внутренние ссылки строятся route helper, а не полными доменными URL.

## 4. Навигация

- [ ] На главной видны шесть ситуационных входов.
- [ ] `/start` одним выбором приводит в нужный раздел.
- [ ] На каждом содержательном экране понятно: где я, что делать, куда дальше.
- [ ] Есть breadcrumbs на разделах и треках.
- [ ] В личном кабинете ровно один главный next action.
- [ ] Альтернативных рекомендаций не более трёх.
- [ ] Если продолжение недоступно, есть возврат в раздел и библиотеку.
- [ ] На mobile есть понятная нижняя навигация участника.

## 5. Честные состояния

- [ ] `metadata_only` не содержит придуманных шагов.
- [ ] При отсутствии контента нет кнопки «Начать».
- [ ] Не показывается «0 из N», если N неизвестно.
- [ ] Нет фиктивной длительности.
- [ ] Реализованы loading, empty, error, locked, planned, not-found.
- [ ] Пустые результаты объясняют, что здесь позже появятся произведённые артефакты.
- [ ] Preview явно отмечен как preview.

## 6. Дизайн

- [ ] Использованы токены из `03_DESIGN_SYSTEM.md`.
- [ ] Нет градиентов, glassmorphism, теней, AI sparkles и стоковых изображений.
- [ ] Цвета A1–A6 используются последовательно.
- [ ] Карточки имеют чёткую типографическую иерархию.
- [ ] На экране не смешано несколько конфликтующих акцентов.
- [ ] Интерфейс проверен на 360, 768 и 1440 px.
- [ ] Нет горизонтального overflow.
- [ ] Ключевые тексты не обрезаются.
- [ ] Hover/focus/active состояния различимы.
- [ ] `prefers-reduced-motion` соблюдается.

## 7. Доступность

- [ ] Доступен skip link.
- [ ] Все интерактивные элементы доступны с клавиатуры.
- [ ] Focus ring видим.
- [ ] Heading hierarchy корректна.
- [ ] Form labels связаны с полями.
- [ ] Статус не передаётся только цветом.
- [ ] Touch targets не меньше 44×44 px.
- [ ] Контраст основных сочетаний соответствует AA.
- [ ] Результаты поиска объявляются через aria-live.

## 8. Код и архитектура

- [ ] TypeScript strict включён.
- [ ] Полный каталог импортируется server-only.
- [ ] Есть `toPublicTrackMetadata()` и тест на sanitizer.
- [ ] Есть repository interfaces для catalog/profile/progress/artifacts/entitlements.
- [ ] UI не зависит напрямую от Local Storage или будущего Supabase.
- [ ] Track Player состоит из переиспользуемых компонентов.
- [ ] Никаких 112 отдельных page-компонентов.
- [ ] Нет молча проглоченных ошибок валидации.
- [ ] Существенные решения зафиксированы в `IMPLEMENTATION_LOG.md`.

## 9. Автоматические проверки

- [ ] Lint проходит.
- [ ] Typecheck проходит.
- [ ] Unit tests проходят.
- [ ] Smoke e2e проходят минимум для главной, библиотеки, раздела, track shell и not-found.
- [ ] Production build проходит.
- [ ] В финальном отчёте указаны реальные команды и результаты, а не обещание «должно работать».

## 10. Запрет на преждевременное наполнение

- [ ] Не создан ни один выдуманный содержательный трек.
- [ ] Не создано ни одного фиктивного упражнения.
- [ ] Не добавлены цитаты или пересказы книги.
- [ ] Не сгенерированы fake user achievements.
- [ ] Будущий content schema существует, но массив `steps` не заполнен производственным контентом.

## 11. Финальный сценарий ручной проверки

1. Открыть `/` на mobile и desktop.
2. Нажать «Найти следующий шаг».
3. Выбрать ситуацию A3.
4. Попасть на A3 и увидеть корректный раздел.
5. В preview найти `A3-002`.
6. Открыть `/track/a3-002`.
7. Увидеть ситуацию, результат, формат и честное `metadata_only`.
8. Увидеть существующие связи продолжения без внутренних полей.
9. Перейти в `/my/route` и увидеть demo-ветку без полного графа из 112 узлов.
10. Открыть неизвестный `/track/a9-999` и получить корректный not-found.
11. Выключить preview flag и убедиться, что planned-каталог исчез из production.

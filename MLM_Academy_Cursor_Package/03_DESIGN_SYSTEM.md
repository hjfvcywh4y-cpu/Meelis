# Дизайн-система MLM Academy

## 1. Визуальная идея

Образ платформы — **рабочая карта действий**.

Это смесь строгой редакционной сетки, производственной маркировки и живых цветовых сигналов. Интерфейс должен чувствоваться как хорошо собранный рабочий стол: понятно, где ты находишься, что делать и какой след останется после действия.

Это не:

- университет с кафедрами;
- мотивационная MLM-сцена;
- корпоративный кабинет;
- детская игровая платформа;
- типовой фиолетовый SaaS;
- «нейросетевой» лендинг.

## 3. Типографика

Рекомендуемая пара:

- заголовки и интерфейс: `Onest`, variable;
- ID, номера и технические подписи: `JetBrains Mono`;
- fallback: `Arial`, `Helvetica`, sans-serif.

Иерархия:

| Стиль | Desktop | Mobile | Применение |
|---|---:|---:|---|
| Display | 72–96 / 0.92 | 42–54 / 0.96 | первый экран |
| H1 | 48–64 / 1.0 | 36–44 / 1.0 | заголовок страницы |
| H2 | 32–40 / 1.05 | 28–34 / 1.05 | секция |
| H3 | 22–26 / 1.15 | 20–24 / 1.15 | карточка/модуль |
| Body L | 20 / 1.45 | 18 / 1.45 | обещание и ситуация |
| Body | 16 / 1.5 | 16 / 1.5 | основной текст |
| Meta | 12–13 / 1.2 | 12 / 1.2 | ID, статус, подпись |

Не делать весь интерфейс жирным. Жирность нужна для порядка чтения, а не для крика.

## 4. Сетка

### Desktop 1440+

- max content width: 1440 px;
- 12 колонок;
- outer margin: 32 px;
- gutter: 16–24 px;
- header: 72 px.

### Tablet 768–1199

- 8 колонок;
- outer margin: 24 px;
- gutter: 16 px.

### Mobile 360–767

- 4 колонки;
- outer margin: 16 px;
- gutter: 12 px;
- нижняя навигация участника: 64–72 px.

На крупных публичных экранах можно показывать тонкие вертикальные линии сетки через background-image. На формах и в Track Player сетка становится тише, чтобы не мешать чтению.

## 5. Формы и геометрия

- базовые карточки прямоугольные;
- радиус 0–8 px;
- граница 2 px чёрная для ключевых карточек, 1 px soft для второстепенных;
- никаких теней;
- допустим один срезанный угол у карточки через `clip-path` или псевдоэлемент;
- срез не должен обрезать focus ring или текст;
- кнопки высотой 48–56 px;
- поля ввода высотой минимум 48 px.

Скошенный угол — подпись языка, а не украшение каждого элемента.

## 6. Базовые компоненты

### Header

- слева знак/название `MLM ACADEMY`;
- по центру основная навигация;
- справа поиск и профиль;
- активный пункт подчёркнут линией или цветной меткой;
- sticky только если не съедает мобильный экран.

### SectionCard

- техническая метка `A1 / 16 треков`;
- короткое название;
- входная ситуация;
- стрелка перехода;
- accent strip/угол раздела;
- вся карточка кликабельна;
- focus visible не менее 2 px.

### TrackCard

- `Track ID` и раздел;
- название максимум 3–4 строки;
- два смысловых блока: «Если…» и «На выходе…»;
- формат;
- статус;
- одна главная кнопка;
- в production planned-карточки не показываются.

### NextActionCard

Самый заметный рабочий блок личного кабинета:

- подпись «Следующее действие»;
- название;
- зачем сейчас;
- результат;
- одна кнопка;
- не более одной такой карточки на экране.

### RouteStepper

- завершённые узлы: спокойный success marker;
- текущий: цвет раздела + чёрная рамка;
- будущий: контур;
- ответвления: максимум три;
- mobile — вертикально.

### StatusBadge

Статус — текст плюс цвет, не только цвет:

- Готовится;
- Доступен;
- Сохранён;
- В работе;
- Ожидает действия;
- Завершён;
- Нет доступа.

### EmptyState

Без мультяшной иллюстрации. Крупное человеческое объяснение, одна причина и один следующий ход.

Пример:

> Здесь пока нет результатов. Они появятся не после просмотра урока, а когда вы сделаете действие и сохраните то, что получилось.

## 7. Композиция главной страницы

1. Header.
2. Hero:
   - техническая подпись `БИБЛИОТЕКА ДЕЙСТВИЙ ДЛЯ MLM`;
   - H1: «Не просто узнать. Сделать следующий результат.»;
   - короткое объяснение;
   - CTA «Найти следующий шаг»;
   - secondary «Открыть библиотеку».
3. Шесть карточек ситуаций A1–A6.
4. Блок «Как это работает»: ситуация → действие → результат.
5. Пример оболочки трека без выдуманного содержания.
6. Объяснение личного маршрута.
7. Финальная CTA.
8. Footer.

Главная B2C не содержит сравнений международных компаний, Leader Cockpit и исследований рынка.

## 8. Композиция библиотеки

- H1 и короткое пояснение;
- строка поиска;
- горизонтальные фильтры или filter drawer на mobile;
- счетчик результатов;
- сетка 3 колонки desktop, 2 tablet, 1 mobile;
- grouped view по разделам как альтернативный режим;
- честный empty state;
- preview banner в dev-режиме.

## 9. Композиция страницы трека

### Desktop

- верх: breadcrumbs и техническая метка;
- основная сетка 8 + 4 колонки;
- слева: название, ситуация, результат и область будущих шагов;
- справа: статус, формат, доступ, будущая фиксация результата;
- внизу на всю ширину: «Куда дальше».

### Mobile

- один поток;
- название;
- ситуация;
- результат;
- статус;
- область содержания;
- sticky action только когда есть реальное действие;
- рекомендации после результата.

В `metadata_only` не рисовать фиктивные шаги. Показывать аккуратный blueprint-состояние: структура готова, содержание в производстве.

## 10. Интеракции

- hover: 2–4 px сдвиг/смена заливки, 140–180 ms;
- active: физическое «нажатие» без теней;
- page transitions минимальны;
- skeleton повторяет реальную геометрию;
- все анимации отключаются при `prefers-reduced-motion`;
- после фильтра/поиска сохранять фокус и объявлять число результатов для screen reader.

## 11. Тон интерфейса

Писать по-человечески и через действие.

Хорошо:

- «Что сейчас мешает вам двигаться?»
- «Выберите ситуацию»
- «На выходе у вас будет…»
- «Продолжение готовится»
- «Вернуться в раздел»
- «Сохранить в мой маршрут»

Плохо:

- «Пройдите образовательный модуль»
- «Освойте компетенцию»
- «Уникальная экосистема обучения»
- «Персонализированный AI-driven learning journey»
- «Станьте лучшей версией себя»

## 12. Доступность

- контраст WCAG AA;
- цвет не единственный носитель смысла;
- touch targets минимум 44×44 px;
- видимый keyboard focus;
- корректные landmark и heading levels;
- skip link;
- aria-live для поиска и ошибок;
- focus trap только в настоящих dialogs;
- не блокировать zoom;
- не использовать текст мельче 12 px.

## 13. Что считать дизайн-дефектом

- одинаковые карточки без ощущения разделов;
- цветной фон на каждом блоке;
- 112 треков, вываленных одной стеной;
- полный граф на мобильном;
- кнопка «Начать», когда контента нет;
- фиктивная длительность;
- внутренние коды P0/P1/P2 в B2C;
- декор, который выглядит как генеративный шаблон;
- тексты книги в публичном интерфейсе;
- отсутствующие empty/error/loading states.

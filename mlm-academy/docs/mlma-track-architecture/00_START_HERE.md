# MLM Academy — передача архитектуры Cursor

## Результат этой итерации

Сейчас нужно не публиковать 112 новых страниц и не включать оплату. Нужно один раз построить в кодовой базе общий каркас, в который затем вставляется любой готовый трек.

После выполнения мастер-промпта в проекте должны существовать:

- реестр всех 112 стабильных Track ID;
- тип каждого ID: самостоятельный трек, исправляющий трек, gate, встроенный инструмент, системное действие или alias;
- серверный Route Engine для активных `RouteRule`;
- единый генератор URL и резолвер сущностей;
- раздельные публичные метаданные и закрытый контент;
- серверная проверка прав `entitlement`;
- выключенные по умолчанию платежи и платная навигация;
- импортёр пакета нового трека;
- тесты, не позволяющие случайно открыть платный контент или активировать архивные стрелки.

## Что передать Cursor

Положить в одну папку контекста Cursor:

1. `01_CURSOR_MASTER_PROMPT_ARCHITECTURE.md` — выполнить первым.
2. `spec/MLM_Academy_Track_Router_v2.json` — машинный источник истины по 112 ID и 58 правилам.
3. `references/MLM_Academy_Track_Matrix_112_v2.xlsx` — человекочитаемая мастер-матрица.
4. `references/Библиотека_онтологии_и_конструкций_треков_v2.xlsx` — определения сущностей, outcomes и переходов.
5. `references/БТ_на_трекеры_v2.docx` — широкие бизнес-требования и приложение A.
6. `references/MLM_Academy_matrix_audit_2026-08-31.md` — решения аудита и запреты.
7. `spec/track-package.schema.json` и `spec/track-package.template.json` — контракт будущего трека.
8. `spec/access-policy.json` — текущая модель доступа и feature flags.
9. `spec/backend-reference-schema.sql` — референс хранилища; Cursor должен адаптировать его к текущему стеку.

Можно дополнительно передать `references/MLM_Academy_Interactive_Map_112_v2.html`, но только как визуальную справку. Она не является источником исполняемой логики.

Не передавать в эту итерацию:

- старую матрицу v1;
- старый JSON-маршрутизатор v1;
- старую интерактивную карту;
- 231 legacy-переход как рабочие правила;
- книги Рыбкина и справочные PDF — они понадобятся при разработке содержания конкретных треков, но сейчас будут засорять архитектурную задачу.

## Порядок работы с Cursor

1. Открыть актуальный репозиторий MLM Academy.
2. Добавить перечисленные файлы в контекст чата Cursor.
3. Вставить целиком `01_CURSOR_MASTER_PROMPT_ARCHITECTURE.md`.
4. Не давать Cursor включать платежи, менять продакшен или создавать содержание отсутствующих треков.
5. После выполнения вставить `03_CURSOR_PROMPT_AUDIT.md` в новый чат Cursor и проверить результат независимо.
6. Каждый следующий готовый трек подключать через `02_CURSOR_PROMPT_INSTALL_TRACK.md`.

## Иерархия источников

При противоречиях Cursor обязан использовать такой приоритет:

1. требования безопасности и доступа из мастер-промпта;
2. `MLM_Academy_Track_Router_v2.json` — ID, типы, canonical ID и исполняемые правила;
3. `references/MLM_Academy_Track_Matrix_112_v2.xlsx`;
4. приложение A в `references/БТ_на_трекеры_v2.docx`;
5. онтологическая библиотека;
6. аудит;
7. интерактивная карта — только визуализация.

## Важное ограничение

Архитектура всех переходов готовится заранее, но нельзя заранее выдумать переходы, которых нет в валидированных данных. В систему импортируются:

- все 112 ID как реестр;
- 58 `RouteRule v2` как правила со статусами;
- правила `VALIDATED_RULE` могут стать исполняемыми только при разрешённых правах;
- `PILOT_DRAFT_TO_TEST` доступны только в административном/пилотном режиме;
- 231 legacy-связь хранится только в документации или архивной таблице и никогда не исполняется Route Engine.

То есть заранее строится весь станок и все посадочные места. Непроверенные детали в него не забиваются молотком.

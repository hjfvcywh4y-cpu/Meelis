# Подготовка оплаты · тестовый режим

Реальные списания и рекуррент выключены.

Клиентская кнопка «Купить в тестовом режиме» **не выдаёт** группы START/FULL и не открывает платное содержание. Сессия Tilda (`tilda_unverified`) для оплаты не используется.

## Сценарий (как будет)

1. Авторизованный пользователь нажимает «Купить».
2. В заказ уходят email и `ma_id`.
3. Создаётся `orderId`.
4. Пользователь переходит к оплате (сейчас — тестовая кнопка на `/access`).
5. Сервер получает подписанный webhook (`server/payment-webhook.js`).
6. Подпись проверяется. Повтор с тем же `idempotencyKey` не создаёт вторую покупку.
7. Пишется платёж, создаётся или продлевается право, пользователь добавляется в группу START/FULL.
8. Возврат на `/my` показывает следующее действие.

Клиентский `PaymentGateway` можно заменить, не трогая кабинет. Сейчас `TestGateway`.

## Сравнение вариантов Tilda

| Сервис | Выдача группы Members | Вебхук / идемпотентность | Рекуррент | Заметка |
|---|---|---|---|---|
| Tilda Payments / ЮKassa в Tilda | Встроенная | Ограничена кабинетом Tilda | Отдельно согласовывать | Проще всего, меньше контроля |
| ЮKassa напрямую | Свой вебхук → группа | Полный контроль подписи | Не включать без решения | Предпочтительна для идемпотентности |
| CloudPayments | Свой вебхук | Подпись уведомлений | Не включать без решения | Карты РФ/СНГ |
| Stripe | Свой вебхук | Стандартный | Не включать без решения | Слабее для РФ |
| PayPal | Свой вебхук | Стандартный | Не включать без решения | Международные платежи |

Секреты в Tilda и клиентский JS не класть. Список env: `server/env.example`.

# Ручные действия владельца · Tilda-MVP

Автоматически обойти публикацию Tilda и настройки Members нельзя.
Ниже: раздел → страница/настройка → поле → старое → новое → как проверить.

## 1. Не переключать все страницы на внешние assets сразу

Живой сайт пока оставить на блоках T123.

Когда будете готовы:

1. Загрузить файлы `tilda/dist/shared/v1/*` на хостинг без секретов (Tilda Files или свой CDN).
2. Выбрать **одну** тестовую страницу, например `/about`.
3. Tilda → страница `/about` → блоки T123 `01-css`, `02-data-*`, `03-domain-*`, `04-ui-*` → удалить/скрыть.
4. Вставить содержимое `tilda/dist/t123/external-loader-v1.html`, заменив `ASSET_BASE` на URL файлов.
5. Mount `mounts/about.html` и HEAD не трогать.
6. Проверить: страница открывается, 112 треков в библиотеке с той же версии, поиск только по кнопке.
7. Rollback: вернуть скрытые блоки T123.

Не публиковать смешанные версии каталога на разных страницах.

## 2. Новые публичные страницы

Создать в проекте 23906986 (папка MLM Academy), **не** добавлять в группы Members:

| Title | URL | Mount | HEAD |
|---|---|---|---|
| Условия доступа · MLM Academy | `/pricing` | `t123/mounts/pricing.html` | `t123/heads/pricing.html` |
| Политика… черновик | `/privacy` | `t123/mounts/privacy.html` | `t123/heads/privacy.html` |

`/privacy` публиковать как черновик. Не называть юридически утверждённой.

После появления страниц обновить sitemap/robots в настройках сайта Tilda (файлы в `tilda/dist/seo/`).

## 3. Members: CSS, JS, пароль, политика

1. Настройки сайта → Личный кабинет / Members → дополнительный CSS
   - старое: пусто или предыдущий фрагмент
   - новое: содержимое `tilda/dist/t123/members-bridge.css`
   - проверить: `/members/login` фон `#f4f0e8`, кнопка `#C45F42`
2. Тот же раздел → дополнительный HTML/JS (если поле есть)
   - новое: `tilda/dist/t123/members-bridge.js`
   - проверить: `/members/login?mlma=recover` открывает сценарий «Забыли пароль?»
3. Favicon Members: Настройки сайта → Favicon → тот же SVG, что в HEAD Академии. CSS favicon не заменяет.
4. Ссылка на политику: внизу форм входа/регистрации добавить `/privacy` вручную, если Tilda не подхватывает футер Академии.
5. Кнопка «Сменить пароль» в профиле Академии ведёт на `/members/login?mlma=recover`. Без JS Members это просто страница входа — нужен шаг 2.

**Не заявлять, что дизайн входа исправлен, пока это не видно на живых `/members/login`, `/members/signup` и восстановлении.**

## 4. Группы Members

Пока UI-галочка и API `addAfterConfirm` расходятся, **не нажимать Save** в настройках групп вслепую.

Нужно:

1. Саморегистрация тестового ящика → подтверждение email → пользователь только FREE, главная `/my`.
2. Editor/ADMIN/START/FULL/PILOT: не добавлять после регистрации.
3. Удалить или ротировать тестовые QA-ящики.

## 5. B2B-навигация

Академия уже ссылается на `/` («Решения для компаний»).
На корпоративной главной `/` добавить ссылку «MLM Academy» → `/academy`.
Корпоративную страницу не перевёрстывать.
Написание «дистрибуцией / дистрибьюцией» править только если оно есть в живом тексте B2B — исходник этой страницы в репозитории не хранится.

См. `docs/LEGAL_GAPS.md`. Не публиковать выдуманную политику как окончательную.

## 7. Worker (когда будете деплоить этот PR)

```
cd mlm-academy/account-proxy
npx wrangler deploy
```

Секреты не печатать. `PAYMENTS_ENABLED` в wrangler.toml = `"false"`.
Ключи ЮKassa и OpenAI в Tilda не класть. Если тестовые ключи уже есть в окружении Worker — не копировать их в git.

## 8. Что не делать

- Не выдавать FULL через bind, localStorage, email или `maId`.
- Не покупать платные сервисы без отдельного решения.

# Развёртывание MLM Academy

## Коротко о главном ограничении

Оболочка не может жить внутри Tilda.

Tilda отдаёт статические страницы, собранные из собственных блоков. Она не
выполняет Node-приложение, не поддерживает маршрут вида `/track/[trackId]` и не
умеет server-only слой и серверные переменные окружения. А именно на них держатся
три обязательных требования постановки задачи:

- полный реестр читается только на сервере и не попадает в браузер;
- предпросмотр включается серверной переменной, а не query-параметром;
- неопубликованный трек отвечает настоящим 404, а не редиректом на клиенте.

Мастер-промпт прямо это фиксирует: «Не привязывай ядро к Tilda. Tilda может
остаться внешней рекламной витриной и вести в приложение».

Поэтому рабочая схема такая:

```
Tilda (витрина, домен, оплата)  ──ссылка──▶  app.<домен> (оболочка MLM Academy)
```

Приложение разворачивается на любой Node-площадке, Tilda ведёт в него по ссылке.
Готовый блок-витрину для Tilda смотрите в `tilda/showcase-block.html`.

## Что нужно от вас

Развернуть приложение автоматически невозможно без доступа к площадке. Нужен
один из вариантов:

| Вариант | Что сделать | Что получится |
|---|---|---|
| Railway | создать новый сервис из этого репозитория, Root Directory `mlm-academy` | тот же аккаунт, где уже живёт бот |
| Vercel | импортировать репозиторий, Root Directory `mlm-academy` | конфигурация не нужна, стек стандартный |
| Свой сервер / Docker | собрать образ из `mlm-academy/Dockerfile` | полный контроль |

Дальше — точные шаги для каждого.

## Вариант A. Railway

1. New Project → Deploy from GitHub repo → выбрать этот репозиторий.
2. Settings → **Root Directory**: `mlm-academy`.
3. Settings → Build: Dockerfile (`mlm-academy/Dockerfile`) — Railway подхватит его
   автоматически при заданном Root Directory.
4. Variables: не задавать `ENABLE_CATALOG_PREVIEW`. Опционально
   `NEXT_PUBLIC_SHOWCASE_URL` — адрес страницы-витрины на Tilda.
5. Networking → Generate Domain или привязать `app.<ваш-домен>`.

Существующий сервис Python-бота при этом не трогается: у него свой корень и свой
`Dockerfile` в корне репозитория.

## Вариант B. Vercel

1. Add New Project → импортировать репозиторий.
2. Root Directory: `mlm-academy`.
3. Framework Preset: Next.js. Build Command и Output Directory менять не нужно.
4. Environment Variables: `ENABLE_CATALOG_PREVIEW` **не задавать** для Production.
   Для окружения Preview можно задать `ENABLE_CATALOG_PREVIEW=true` — тогда
   закрытые ссылки Vercel покажут все 112 карточек, а прод останется чистым.
5. Domains: привязать `app.<ваш-домен>`.

## Вариант C. Docker где угодно

```bash
cd mlm-academy
docker build -t mlm-academy .
docker run --rm -p 3000:3000 mlm-academy
# закрытый стенд с предпросмотром:
docker run --rm -p 3000:3000 -e ENABLE_CATALOG_PREVIEW=true mlm-academy
```

## Переменные окружения

| Переменная | Production | Закрытый стенд |
|---|---|---|
| `ENABLE_CATALOG_PREVIEW` | не задавать | `true` |
| `ENABLE_ADMIN_CATALOG` | не задавать | `true` при необходимости |
| `NEXT_PUBLIC_SHOWCASE_URL` | ссылка на витрину Tilda, необязательно | то же |

Значения задаются только в панели площадки или в локальном `.env.local`.
В репозитории лежит `.env.example` — имена без значений.

## Проверка перед публикацией

```bash
cd mlm-academy
pnpm install
pnpm lint && pnpm typecheck && pnpm test && pnpm build && pnpm e2e
git status --porcelain     # не должно быть .env и других незакоммиченных секретов
grep -rn "ENABLE_CATALOG_PREVIEW" .env* 2>/dev/null   # только .env.example, без значения
```

## Проверка после публикации

1. `/` открывается, шесть входов на месте, баннера предпросмотра нет.
2. `/library` показывает честное состояние подготовки каталога.
3. `/library/a3` открывается, готовящиеся треки не видны.
4. `/track/a3-002` отвечает 404 (трек ещё не опубликован).
5. `/track/a9-999` отвечает 404.
6. `/admin/catalog` отвечает 404.
7. `/my`, `/my/route`, `/my/results`, `/profile`, `/access` открываются.
8. В исходном коде страницы нет строк `Осовременивание`, `pageStatusRaw`,
   `mlmacademy.ru/track`, `P0`.
9. Ширина 360 px: нет горизонтальной прокрутки, нижняя навигация на месте.

Быстрая проверка статусов одной командой:

```bash
BASE=https://app.example.com
for u in / /library /library/a3 /track/a3-002 /track/a9-999 /admin/catalog; do
  printf '%-22s %s\n' "$u" "$(curl -s -o /dev/null -w '%{http_code}' "$BASE$u")"
done
# ожидаем: 200 200 200 404 404 404
```

## Как подключить Tilda

1. В проекте «Академия партнерских сетей и дистрибьюции», в папке `MLM Academy`,
   создайте страницу-витрину.
2. Добавьте блок **T123 «HTML-код»** и вставьте содержимое
   `tilda/showcase-block.html`.
3. В начале файла замените `https://app.example.com` на реальный адрес приложения.
4. Опубликуйте страницу.

### Про оплату

Оплату на этом этапе подключать нельзя: в оболочке ещё нет ни одного трека с
содержанием, а продавать пустую библиотеку нечестно и технически бессмысленно.

Когда содержание появится, есть два рабочих пути:

- **Быстрый.** Оплата и доступ живут в Tilda (Tilda Payments + Members). После
  оплаты участник получает ссылку в приложение. Минус: приложение не знает о
  статусе оплаты и не может закрыть отдельные треки.
- **Правильный.** Оплата приходит вебхуком в приложение и превращается в
  entitlement. Оболочка к этому уже готова: есть `EntitlementRepository`, статус
  `Нет доступа` и поле `access` у каждого трека. Нужно добавить БД (Supabase),
  авторизацию и обработчик вебхука.

Выбирать стоит после появления первых опубликованных треков.
